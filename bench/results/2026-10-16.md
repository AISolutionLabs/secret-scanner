# Benchmark results, 2026-10-16

Follows [2026-10-15](2026-10-15.md), which has the first, untuned CredData
run, the leaky-repo runs, corpus adjudication and the regression suite in
detail. This round answers the review's open points: triage losing real
secrets, the balanced policy's low blocking recall, and reproducibility.
Everything below can be regenerated with `bench/reproduce.sh` (pinned tools
and datasets), locally or with the `benchmark` workflow in a fork.

| Component | Version |
|---|---|
| secretscan | this commit, Go 1.24.7, linux/amd64, 2 vCPUs |
| gitleaks | v8 built from source at b58d3f1 (2026-07-22), default config |
| detect-secrets | 1.5.0, `--no-verify` |
| CredData | Samsung/CredData @ 0b1940e (2026-09-29) |

## Method: a holdout inside CredData

The changes below were informed by CredData, which would make CredData
numbers optimistic. To keep an honest measurement, the repositories were
split before any per-half result was looked at: a repository is **dev** if
the first hex digit of `sha256(RepoName)` is 0-7, otherwise **test**
(`bench/creddata.py --split`). That gives 156 dev and 181 test repositories,
with 8,902 and 3,836 labeled secrets: a few large repositories fall in dev.
Changes were designed and iterated on dev only. The test half was scored
once before the changes and once after. All-repository numbers are reported
too, but they include the dev half and are no longer independent.

## 1. Triage: conservative mode

Standard triage applied shape-only filters (identifier, UUID, word-like, ...)
regardless of context, and on CredData that dropped real secrets: UUID access
tokens, hex values in `KEY=value` files, pagination tokens, base64 under
`key =`. Conservative mode, now the default, does not apply shape-only
filters to a value under a credential-named key, except for namespaced
identifiers, values that name a secret, and UUIDs under request-style keys.

**Test half (never used for design), secrets-only labels:**

| | True | False | Precision | Recall | Real secrets lost vs gitleaks |
|---|---|---|---|---|---|
| gitleaks | 1,110 | 99 | 91.8% | 28.9% | – |
| gitleaks + triage, before | 980 | 72 | 93.2% | 25.5% | 130 |
| gitleaks + triage, standard mode | 987 | 73 | 93.1% | 25.7% | 123 |
| **gitleaks + triage, conservative (default)** | **1,095** | **79** | **93.3%** | **28.5%** | **15** |

Conservative triage keeps 98.6% of gitleaks' true findings and removes 20%
of its false positives on unseen repositories. The 15 it still loses are
mostly base64-encoded JSON tokens (`eyJr…` Grafana-style keys) and values
under keys it does not recognise as credential names.

Dev half, for reference: gitleaks 5,861 true / 1,026 false; triage before
5,625 / 453; conservative 5,843 / 459.

On the regression suite, conservative triage still filters all 91
issue-derived false positives and keeps all 435 of gitleaks' true findings.
Its cost is review volume on published packages: 5.04 findings per 1,000
files listed for review instead of 2.05; blocking findings under balanced are
unchanged (0.97).

## 2. Detection fix found on the dev half

Unquoted lowercase hex (`SharedSecret=e86f3aba…`, `Key = acc993b3…`) was
classed as a code identifier, in scans as well as triage, because the
letter-run split of hex looks like short words. Hex with both letters and
digits is now treated as data. Test half, standalone secretscan:

| | True | False | Precision | Recall |
|---|---|---|---|---|
| before | 1,835 | 343 | 84.3% | 47.8% |
| after | 1,843 | 358 | 83.7% | 48.0% |

A wash on the holdout (+8 true, +15 false: hex test vectors labeled as
non-secrets), kept because dropping real hex keys silently is the worse
failure. On this half gitleaks' precision (91.8%) is clearly higher than
secretscan's (83.7%); secretscan's recall is higher (48.0% vs 28.9%).

## 3. Balanced policy: test fixtures block by default

| Policy (all repositories) | Blocking recall | Blocking precision |
|---|---|---|
| strict | 68.7% | 85.0% |
| balanced, before this release (high only) | 14.4% | 92.3% |
| balanced, `testFixtures = "review"` | 17.5% | 88.1% |
| **balanced, `testFixtures = "block"` (default)** | **59.9%** | **91.6%** |

On the test half: strict 48.0% / 83.7%, balanced with fixtures blocking
34.3% / 85.9%, balanced with fixtures reviewed 19.6% / 81.6%.

Blocking generic values in test/example files raises recall and precision on
real repositories. On published packages, whose test suites ship many fake
credentials, blocking findings rise from 1.85 to 2.69 per 1,000 files, so
fixture-heavy repositories can set `testFixtures = "review"`. This setting is
a policy choice informed by all of CredData, not a detection change.

## 4. Unchanged

- Regression suite: 529/529 labeled secrets found and blocking under
  balanced, 40/40 safety cases, 0/91 issue-derived false positives.
- Package corpus adjudication: 132 findings, 0 live credentials, 116 example
  credentials, 16 false positives (0.36 per 1,000 files).
- Noise filters remove at most 0.025% of any random-secret alphabet at 20,000
  samples (the password alphabet; CI limits are 0.05% for passwords and 0.02%
  for every other alphabet).
