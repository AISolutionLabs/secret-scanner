# Benchmark results, 2026-10-17

Follows [2026-10-16](2026-10-16.md). This round added placeholder ("dummy")
recognition, local/example credential context, new detectors (HTTP Basic and
Bearer headers, SQL passwords, environment and command-line passwords, token
setters, UUID tokens under credential keys) and the fixes from an adversarial
review. All of it was designed on CredData's **dev** half only; the **test**
half (181 repositories) was measured once, after everything was merged.
Regenerate with `bench/reproduce.sh`.

¹ Added the same day from the same gitleaks report (only `triage` re-run);
the figure was quoted in the docs without a row here.

Official labels: secretscan 91.5% / 47.4% (before 83.7% / 38.5%), gitleaks
91.8% / 23.2%, gitleaks + triage 93.6% / 22.1%, trufflehog 44.9% / 2.8%.

What this shows:

- On unseen repositories secretscan's precision rose from 83.7% to 91.5%,
  level with gitleaks (91.8%), while it finds twice as many of the labeled
  secrets (59.2% vs 28.9%).
- The dev half reached 98.8% precision and 89.0% recall; most but not all of
  that transferred. Part of the dev gain came from CredData's obfuscation
  (true secrets are random characters, false ones are often words), which
  flatters placeholder recognition.
- Triage now drops 54 of gitleaks' true findings instead of 15. 41 of them
  are AWS WAF `ChangeToken` values, which are deliberately no longer treated
  as credentials (they order updates and grant no access; CredData labels
  them true). Without those, triage loses 13 (15 before). It removes 27 of
  gitleaks' 99 false positives.

## 3. Calibration (secrets-only, one finding per line)

| Test half | High | Medium | Low |
|---|---|---|---|
| true / false | 601 / 72 | 252 / 51 | 1,416 / 87 |
| precision | 89.3% | 83.2% | 94.2% |

| Test half, context | local | example | none |
|---|---|---|---|
| true / false | 98 / 5 | 0 / 0 | 2,171 / 205 |

Confidence is **not** calibrated to CredData's labels: low-confidence
findings are the most precise. CredData labels credential-shaped values in
test directories as real, and those are exactly the generic values capped at
low. Confidence measures the strength of the evidence that a value is a live
credential in production code, which is what blocking uses; it is not the
probability that CredData labels a line true. Local-context credentials are
real credentials (95% precision); they are reported and reviewed, not
blocked, under balanced.

## 4. Adversarial review

A separate reviewer that had not seen the work crafted realistic inputs and
reviewed triage, verification and fixes. Fixed (details in
[docs/security-audit.md](../../docs/security-audit.md), findings 8-13):

- weak real passwords in production config (`admin@123`, `Welcome1!`) were
  dropped as placeholders under every policy; now reported at low confidence;
- production hosts under `*.svc.cluster.local`, `.env.local` files and
  production compose files were treated as local; now block;
- empty-user URLs (`redis://:pw@host`) and unquoted base64 values starting
  with `/` or `+` were never matched;
- `--verify` treated a TLS-inspecting proxy's HTML page as "verified", and a
  401 from github.com/gitlab.com as "invalid" for enterprise tokens;
- `--fix` rewrote literals inside comments, raw and triple-quoted strings and
  constant contexts in several languages;
- oversized inputs were skipped silently; SARIF triage output lost the
  source tool and status.

The trade-offs that can still hide a real credential are listed in
[docs/precision.md](../../docs/precision.md#trade-offs-that-can-hide-a-real-credential).

## 5. Unchanged guarantees

- Regression suite: 529/529 labeled secrets found and blocking under
  balanced, 40/40 safety cases, 0/91 issue-derived false positives.
- Package corpus (44,284 files, every finding labeled by hand): 0 live
  credentials, 118 example credentials, 16 false positives (0.36 per 1,000
  files). Reported noise 3.03, blocking 2.75 per 1,000 files.
- Noise filters stay within the per-alphabet false-negative limits, plus a
  new "placeholder-vocabulary-adjacent" alphabet (random values around one
  placeholder word).
- leaky-repo: 65/96 risk lines (66 before; gitleaks 21, trufflehog 10,
  detect-secrets 37). One new line in `.bash_profile`; two lost on purpose:
  `IRC_PASS=irc_pass` (value repeats its key) and
  `mongodb://testuser:testpass@…`, now recognised as placeholders.

## 6. Breakdown of the holdout run

Added the same day from the report behind section 1, with
`bench/breakdown.py`: a re-scoring of the existing report, not a new run of
the test half. Secrets-only labels; paths classified with the scanner's own
test/example-path rule. A true line reported by findings in two groups
counts in both.

| Policy | True | False | Precision | Recall |
|---|---|---|---|---|
| strict (detection) | 2,271 | 210 | 91.5% | 59.2% |
| balanced, testFixtures = "block" (default) | 1,531 | 166 | 90.2% | 39.9% |
| balanced, testFixtures = "review" | 853 | 123 | 87.4% | 22.2% |

| Confidence | True | False | Precision |
|---|---|---|---|
| high | 601 | 72 | 89.3% |
| medium | 252 | 51 | 83.2% |
| low | 1,426 | 87 | 94.2% |

| Path | True | False | Precision |
|---|---|---|---|
| other path | 746 | 102 | 88.0% |
| test/example path | 1,525 | 108 | 93.4% |

| Context | True | False | Precision |
|---|---|---|---|
| local | 98 | 5 | 95.1% |
| none | 2,173 | 205 | 91.4% |

| Detector family | True | False | Precision |
|---|---|---|---|
| generic | 1,590 | 148 | 91.5% |
| provider format | 693 | 62 | 91.8% |

| Confidence by path | True | False | Precision |
|---|---|---|---|
| high, other path | 406 | 46 | 89.8% |
| medium, other path | 252 | 51 | 83.2% |
| low, other path | 88 | 5 | 94.6% |
| high, test/example path | 195 | 26 | 88.2% |
| low, test/example path | 1,338 | 82 | 94.2% |

- **Detection vs blocking recall**: strict reports 59.2% of the labeled
  secrets; balanced blocks 39.9% (default `testFixtures = "block"`) or 22.2%
  (`testFixtures = "review"`). The rest is reported for review.
- **Confidence is not a probability.** 1,338 of the true lines are generic
  values in test or example paths, where CredData labels credential-shaped
  fixtures as real and secretscan caps them at low. That is most of why low
  is the most precise level. In other paths high (89.8%) is more precise
  than medium (83.2%), but the 93 low findings there are 94.6% precise too
  (of the 99 low findings outside test paths, 69 have few supporting
  signals and 30 are local-context credentials; CredData labels most true).
  Confidence ranks the strength of evidence, not the chance a label is true.
- **Provider formats in test paths are not downgraded**: they stay high
  (195 true, 26 false, 88.2%) and block under every policy.
- **Provider formats and generic rules are equally precise** (91.8% and
  91.5%).

## 7. Label disagreements

CredData labels 42 of the missed true lines on the test half as secrets
that secretscan deliberately does not report: AWS WAF `ChangeToken` values,
which order WAF updates and grant no access. Every headline figure uses
CredData's labels as given; excluding these lines, detection recall would be
59.9% instead of 59.2%. The policy for such disagreements is in
[docs/benchmark-policy.md](../../docs/benchmark-policy.md).
